# CLAUDE.md — JRA platform

Project context. Read this before making changes.

## What this is

The Jordan Restaurant Association platform: a bilingual (EN/AR, RTL) Next.js 15
app on Postgres via Prisma, with a public sector gateway, a member portal and an
admin panel.

It is the merge of two projects — this platform (database, auth, admin, portal)
and a separate, design-audited public front end that was ported in. **If you are
touching anything under `src/app/[locale]/` that is not `admin/` or `portal/`,
read [docs/FRONTEND-PORT.md](docs/FRONTEND-PORT.md) first.** It explains the
design layer, the data bridge and the conventions below, with the reasoning.

## Stack

Next.js 15 (App Router) · React 19 · TypeScript (strict, `noUncheckedIndexedAccess`)
· Prisma 6 + Postgres 16 · NextAuth 5 (credentials) · next-intl 3 · Tailwind v4
+ CSS Modules · Cloudinary (with local-disk fallback) · vitest

## Setup in one block

```bash
docker compose up -d
cp .env.example .env                      # then: localhost -> 127.0.0.1 in both URLs
npx auth secret                           # paste into AUTH_SECRET
npx prisma migrate deploy && npx prisma generate
npm run seed:suppliers && npm run seed:legacy-images && npm run data:directory
npm run seed:admin                        # admin@jra.jo / ChangeMe123! (local only)
npm run dev
```

Full detail, including seeding from spreadsheets, is in `CONTRIBUTING.md`.

## The things that will catch you out

1. **Seed scripts do not read `.env`.** They run under `tsx`. Wrap them:
   `npx dotenv -e .env -- tsx prisma/seed/<script>.ts`.
2. **Use `127.0.0.1`, not `localhost`,** in `DATABASE_URL` / `DIRECT_URL`. Docker
   binds 5433 on IPv6 too, and on Windows `localhost` hits `::1` first.
3. **The public directory reads `src/data/*.json`, not the database.** It is
   generated by `npm run data:directory` (and by `npm run build`). Admin edits do
   not appear on the public site until it reruns. This is deliberate — the
   directory filters client-side. Do not convert it to per-request queries.
4. **Stop the dev server before building.** `prisma generate` hits `EPERM` on the
   query-engine DLL otherwise, and the build reports success without building.
5. **A stale `.next` can serve a loading fallback forever** with the real markup
   stranded in a hidden div, as a 200 with no error. `rm -rf .next`.
6. **`.env.production.local` points at production** and wins in production mode,
   so `npm start` can silently serve the live database. Move it aside to test
   locally.

## Conventions

- **Logical CSS properties only.** No `left`/`right`, `margin-left`,
  `text-align: left`, `padding-right`. `<html dir>` mirrors the layout; physical
  properties break Arabic. Only `.mirror` (arrows, chevrons) flips physically.
- **Arabic is not styled like Latin.** No italic, no letter-spacing, no
  uppercase — each damages Arabic script specifically. The corrections live in
  `globals.css` and apply to the Tailwind utilities, so new markup inherits them.
- **`import { Link } from "@/i18n/navigation"`**, never `next/link`.
- **Two colours only** — blue `#0053A0`, grey `#6C6D70`, plus their tonal
  derivations. Status colours (success/warning/danger) are the sole exceptions
  and are for status only. Measure any new pair against WCAG AA.
- **Interactive controls use `--color-field-border`**, not `--color-rule` — a
  control boundary needs 3:1, the decorative hairline is ~1.2:1.
- **Editorial prose** lives in `src/lib/content.ts` / `src/lib/modules.ts` as
  `{ en, ar }` pairs read through `pick()`. **Interface chrome** lives in
  `messages/*.json` read through next-intl. Do not mix the two.
- **Uploads go through `src/lib/storage.ts`.** Never `fs.writeFileSync` in a
  server action — production is a read-only serverless filesystem.
- **Every export of a `"use server"` module becomes a Server Action.** Do not put
  plain read helpers in one; give them their own module (this bit us once — see
  `src/lib/site-settings.ts`).
- **Public forms are rate limited** (`src/lib/rate-limit.ts`): 5/hour/IP for
  contact and membership, 10 for newsletter.

## Testing

```bash
npm test          # vitest, 82 tests — no server, no database, keep it that way
npm run smoke     # 46 route checks against a running server
npm run typecheck
```

Check `/en` **and** `/ar` for anything visual. RTL breaks in ways that are
invisible in English.

## Known gaps

- Five routes still carry the platform's original design because the ported
  front end has no counterpart: `classification/[type]`, `legal/[slug]`,
  `magazine/[id]`, `marketplace/[id]`, `newsletter`.
- News, magazine and training pages render hard-coded editorial prose rather than
  the `NewsArticle` / `MagazineIssue` / `Course` tables that exist for them.
- Cuisine and amenity tags have no Arabic names in the database (English-only
  source), so Arabic pages show English category labels.
- Supplier records are directory-level only; the B2B module (profiles, RFQ,
  group buying) is still Phase 3 per `docs/PLATFORM-BLUEPRINT.md`.

## Never commit

`.env*`, `public/uploads/restaurants/`, `public/uploads/membership-documents/`,
the `JRA/` source folders. The rest of `public/uploads/` **is** committed on
purpose — seeded rows point at those paths.

**Never push to `main`.** Vercel deploys it straight to the live public site.
